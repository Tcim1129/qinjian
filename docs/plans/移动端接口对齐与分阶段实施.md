## 3. 阶段 1：打通端到端主链

目标链路：**手机说一段话 → 转文字 → 改写 → 自己确认 → 保存结果**

移动端代码已接好全链，只缺后端：

| 环节 | 移动端调用 | 目标后端接口 | 现有对应 |

| 能力预检 | `loadPreflight` | `POST /mobile/preflight` | 无（新增） |

| 语音票据 | `issueMobileRealtimeVoiceTicket` | `POST /mobile/realtime-voice/tickets` | `POST /agent/asr/ws-ticket` |
| 转写 | （WebSocket） | `/agent/asr/realtime` | 已存在 |
| 改写 | `simulateMessage` | `POST /mobile/communication/simulations` | `POST /agent/simulate-message` |
| 确认反馈 | `submitMessageSimulationFeedback` | `POST /mobile/communication/simulations/feedback` | `POST /agent/decision-feedback/{event_id}` |

阶段 1 需实现约 15 个接口，其中真正新增能力：

- `preflight`、`bootstrap`（移动端启动协议）
- `checkins` 的可见性语义（`private` / `shared_summary` / `shared_original`）——**现有后端没有，属共享边界，需单独设计**
- 媒体分阶段上传（preflight / upload / access / discard）

**语义映射不可直接转发**：移动端用 `scope`(`solo`|`relationship`) + `relationship_space_id`，后端用 `pair_id` + `mode=solo`，必须显式转换。

### 6.2 架构分叉：两套 agent 子系统

基线 `bef387b` **没有** agent 子系统，两线各自独立造了一套：

| | 网页线 | 语音线 |
| --- | --- | --- |
| 循环 | `agent_loop.py`（返回 `tuple[str, steps, bool]`） | `agent_loop.py`（返回 `AgentLoopResult`，proposal-only） |
| 工具 | `tools.py` | `agent_tools.py` |
| 编排 | `multi_agent.py`、`skills*`、`conversation.py` | `emotimirror_agents.py` |
| `agent.py` 调用 | `multi_agent` / `tools` / skills / thoughts / task_proposals | `loop_result` / `agent_trace` / `emotimirror_guardian` |

两侧 `run_agent_loop` 签名与返回值不兼容，`multi_agent.py`（仅网页线有）和网页线测试依赖 tuple 契约，语音线 `agent.py` 依赖 `AgentLoopResult`。**必须二选一并改造另一侧调用方**，不能并存。

### 6.3 危机通知语义冲突（安全性）

`_create_crisis_notifications`：

- 网页线：`(db, pair, ...)` → **通知配对双方**，带升级文案。
- 语音线：`(db, *, owner_user_id, ...)` → **只通知本人，明确禁止广播给伴侣**，并带专门测试 `test_crisis_notification_privacy.py`。

语音线版本是隐私加固，倾向保留；但它是**行为变更**，需要与网页线调用方一起改。

### 6.4 修正策略（推荐）

原方案「两线合并成单链」在当前状态下代价高、风险大。改为：

1. **产品主线采用网页线**（`wip/web-line`）：它含产品面超集（`expressions`、`agent_skill`、agent 子系统、web-vue3），且迁移**已是单 head**（`0023 → f8cb → a1b2 → 7c5e`），不需要合并即可升级。
2. **`/mobile/*` 接口层直接在网页线上开发**：阶段 1 的移动端主链不依赖 agent 循环，也不依赖 emotimirror 模型。
3. **语音线（emotimirror）保持独立推进**：与最初计划「本人音色合成单独推进」一致；待 agent 层分叉方案定案后再做定向集成，而不是整包 merge。
4. 迁移编号重叠问题因此**暂不触发**：不合并就不会出现双 head。

### 6.5 若将来要合并语音线

不要整包 merge。建议按「网页线为基线 + 定向移植」：

- 迁移：删语音 `0024`，把语音 `0025` 的 `down_revision` 指向 `7c5e9210abcd`（已验证可行，见 2.1）。
- 模型：以网页线 `models/__init__.py` 为基线，**逐类追加**语音线独有的 emotimirror 模型（不要按冲突块取并集，冲突区会切断类定义）。
- agent 层：先定案循环契约（建议保留网页线 `agent_loop.py`，把语音线的 proposal-only 与 `emotimirror_guardian` 作为定向改动叠加）。
- 危机通知：采用语音线的 owner-only 版本，并同步改网页线调用方。
- 每步跑后端全量回归。
