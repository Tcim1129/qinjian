## 实施

1. **真实改写与失败状态**：修改 `backend/app/ai/message_simulator.py`，保留确定性的风险判断，模型失败、空回复和格式错误明确失败；有效的原句保留不被强制换成模板。在现有 API 中映射可重试错误。
2. **私密保存**：新增 owner 绑定的表达表、迁移、服务与 API。只存本人确认后的文字，不额外存录音；保存具备幂等性，列表/删除按账号隔离，不以配对身份开放内容。纳入现有隐私删除流程。
3. **原页面补齐操作**：推荐改写可直接编辑、复制和保存；提供最近保存列表与删除。空内容不可保存，失败不清空输入，切换账号/关系后旧异步响应不得回填。样例不写入真实收藏。
4. **验证与交接**：运行后端行为测试、前端检查/构建和桌面/移动宽度浏览器操作。外部模型、麦克风、手机设备和生产数据库不因离线测试通过而宣称已验收。

## 验收重点

- 格式错误、供应商异常、超时均不产生预设改写或成功保存记录。
- 模型保留原句时不会被替换为固定话术；模型不得覆盖规则判断的最低风险。
- 保存的是编辑框里的最终文字；重试同一请求不会生成重复记录。
- 其他账号无法查看或删除；删除本人隐私数据会清除保存的表达。
- 切换对象、账号或离开页面时，过期结果不覆盖当前输入、编辑或列表。
- 手机宽度可操作、没有横向溢出；按钮文案短，保留必要的私密状态和错误信息。

## 后续边界

新的小程序/App 需单独对齐本次 API、录音权限与真机验证。EmotiMirror 的身份复验、封闭语音投递和共同胶囊仍按独立计划推进；不直接合并存在编号冲突的旧数据库迁移链。
