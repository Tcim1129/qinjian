# ADR-001：亲健 Web 主线与迁移期间双前端边界

- 状态：已接受
- 日期：2026-07-17
- 范围：阶段 0 与后续 Web 收敛；不授权小程序、App、支付或生产部署

## 背景

当前仓库同时存在两套 Vue 3 前端：

- `qinjian-ui-preview` 已形成暖米白、陶橙、纸艺场景和去医疗化的新版视觉，并已直接连接正式后端适配层；
- `web-vue3` 覆盖更多历史路由、演示夹具和成熟的功能分支，是核对接口与边界状态的重要来源。

两套路由模式也不同：新版使用 hash history，旧版使用 history。此差异属于迁移风险，不能用“页面看起来已有”代替深链、刷新和 Nginx 回退验证。

当前代码而非规划文档是实现真值。业务接口以 `backend/app/api/v1`、新版 `src/services/realApi.js` 和旧版 `src/api/index.js` 的实际契约为准；产品取舍以 `docs/product/product-boundary.md` 为准；两端当前差异以 `current-feature-matrix.md` 为准。

## 决策

1. `qinjian-ui-preview` 是唯一 Web 视觉与交互主线，后续 Web 页面以它的品牌、布局、响应式和可访问性基线收敛。
2. `web-vue3` 是功能对照源，不再作为新视觉方向，但其已验证的接口、状态处理、演示夹具和边界测试必须逐项核对。
3. 在功能对齐、真实/样例数据隔离、深链回归和端到端测试全部完成前，不删除、不归档、不覆盖任何一套前端。
4. 不以路由名称相同作为“已迁移”。每个能力必须同时通过五项门槛：路由、接口、真实数据状态、样例数据隔离、视觉状态。
5. 新版已有的旧路径别名或重定向只用于兼容；正式信息架构最终另行决策，Task 1 不改路由和业务代码。
6. 阶段 0 不执行目标仓库重排，不创建 `apps/mobile`，不接支付，不修改部署入口。

## 迁移门槛

每一行功能只有在以下证据齐全后才能标记为“可替代旧版”：

- 路由：直接访问、刷新、鉴权重定向和旧深链均通过；
- 接口：请求方法、参数、错误码、超时和权限语义一致；
- 真实数据：加载、空、失败、未配对、待确认和多关系状态不伪造；
- 样例数据：明确标识、与真实账号隔离、不得写入真实后端；
- 视觉状态：1440、1280、1024、768、390、360 宽度，无横向滚动，键盘和减少动态设置可用；
- 回归：两套既有测试、迁移检查脚本及相关浏览器用例均通过。

任何一项未完成时，旧版仍保留为只读功能对照，不宣称迁移完成。

## 影响

正向影响：视觉决策只有一个主线；历史功能不会因提前删库而丢失；样例和真实数据的差异成为显式验收项。

成本与风险：短期继续维护两套依赖和路由；hash/history 差异需要专项回归；旧版存在 P2 空壳与硬分数表达，不能直接照搬其产品语义。

## 明确不做

- 本 ADR 不批准删除 `web-vue3` 或重命名 `qinjian-ui-preview`；
- 不批准小程序、App、支付、订阅权益或生产部署；
- 不把页面中现有“关系总分”视为专业结论；
- 不把演示账号、静态样例或占位数据当作真实用户验证。

## 复审条件

只有当矩阵所有 P0 项均有完整证据、两套测试与端到端回归通过、真实/样例数据隔离验证完成后，才召开归档评审并另写 ADR。删除任一前端需要新的显式决策。
